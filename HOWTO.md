# Money Graph: инструкция для аналитика и команды

## 1. Что делает проект и кому он нужен

Money Graph помогает AML-аналитику выбрать, какие связи и счета проверить первыми в предоставленной сети переводов за июль 2026 года. Программа сопоставляет входящие и исходящие переводы, предлагает роль для каждого из 2 248 узлов, объединяет связанные узлы в группы и составляет список приоритетов. В карточке выбранного `gid` видны конкретные суммы, число плательщиков и получателей, направление переводов и объяснение правила. Результат — гипотезы для дальнейшей проверки; данные не позволяют установить личность клиента, его полный баланс или намерения.

## 2. Что означает каждый выходной файл

### `out/nodes_roles.csv`: все узлы

В текущем результате **2 248 строк**, включая **19 изолированных seed** — исходных участников, для которых в выгрузке нет ни одного ребра.

| Столбец | Значение для аналитика |
|---|---|
| `gid` | Синтетический идентификатор клиента. Сохраняйте все цифры: идентификатор нужно копировать как текст. |
| `role` | Гипотеза об основной роли: `consolidator` — собирает средства; `transit` — пересылает сопоставимый объём; `distributor` — переводит многим получателям; `terminal` — исходящие в выгрузке не видны; `coordinator` — заметный посредник в направленных путях; `peripheral` — сильного сигнала роли нет. |
| `role_score` | Значение от 0 до 1, назначенное объяснимым правилом. Отражает условную силу признаков и ограничения наблюдения. Это не измеренная вероятность правильности роли. |
| `cluster_id` | Номер группы, к которой отнесён узел. Его можно найти в `clusters.csv` и выбрать в интерфейсе. |
| `priority_score` | Приоритет проверки от 0 до 1: комбинация процентильных рангов пяти сетевых признаков. Чем выше, тем раньше узел попадает в список проверки. |
| `evidence` | Объяснение длиной до 200 символов: число контрагентов и переводов, суммы или доля пересылки, а также необходимые оговорки о неполноте данных. |

`terminal` требует чтения пояснения: на глубине 4 нулевые исходящие могут возникнуть из-за остановки обхода. У таких узлов оценка **0,45** и явное предупреждение. До глубины 4 оценка составляет **0,82** для не-seed и **0,50** для seed с входящими переводами.

### `out/clusters.csv`: группы узлов

В текущем результате **91 группа**. Сообщество отражает наблюдаемые связи; его наличие само по себе не устанавливает общую организацию или цель участников.

| Столбец | Значение для аналитика |
|---|---|
| `cluster_id` | Номер группы; совпадает с номером у её узлов. |
| `n_nodes` | Сколько узлов входит в группу. |
| `n_seed` | Сколько из них относятся к исходным seed. |
| `sum_kzt_internal` | Сумма переводов по направленным рёбрам, у которых оба конца внутри группы. Межгрупповые переводы сюда не входят; это оборот, а не остаток средств. |
| `top_gids` | До пяти узлов группы с наибольшим приоритетом. Идентификаторы разделены точкой с запятой. |
| `hypothesis` | Рабочая гипотеза по составу группы: количество seed, узлов с заметными ролями и внутренний оборот. |

### `out/top_nodes.csv`: очередь проверки

По умолчанию экспортируются **100 узлов**. Параметр `--top N` меняет длину списка; минимально запрашивается 20.

| Столбец | Значение для аналитика |
|---|---|
| `rank` | Место в списке: 1 — первый кандидат для проверки. |
| `gid` | Идентификатор, который нужно вставить в поиск интерфейса. |
| `role` | Та же гипотеза роли, что в полном списке узлов. |
| `priority_score` | Тот же приоритет, что в полном списке; строки идут по убыванию. |
| `why` | Приоритет и числовое объяснение роли. |

Дополнительно создаются `out/index.html` — экран просмотра, и `out/analysis_summary.json` — машинная сводка чисел, порогов и времени расчёта. Формулы, порядок правил и точные пороги приведены в [README.md](README.md). Результаты проверки безопасности — в [SECURITY.md](SECURITY.md), полный аудит — в [AUDIT_REPORT.md](AUDIT_REPORT.md).

## 3. Как запустить самостоятельно

Команды ниже рассчитаны на PowerShell и текущую папку проекта `C:\hackalemai`. Нужен Python 3.10 или новее. Для предоставленных Markdown-таблиц устанавливать библиотеки не требуется.

**Шаг 1. Откройте проект и проверьте Python.**

```powershell
cd C:\hackalemai
python --version
```

**Шаг 2. Подготовьте входные файлы.** В `data` должны лежать `nodes.md`, `edges.md`, `transactions.md`. В текущей рабочей папке они уже есть. После нового клонирования их нужно скопировать из предоставленного набора: `data/` и `out/` намеренно исключены из Git.

Для файлов из Downloads на этой машине:

```powershell
New-Item -ItemType Directory -Force .\data | Out-Null
Copy-Item -LiteralPath 'C:\Users\mstit\Downloads\nodes.md' -Destination .\data\nodes.md
Copy-Item -LiteralPath 'C:\Users\mstit\Downloads\edges.md' -Destination .\data\edges.md
Copy-Item -LiteralPath 'C:\Users\mstit\Downloads\transactions.md' -Destination .\data\transactions.md
```

На другой машине замените исходные пути местом хранения выданного набора. Используйте все три таблицы из одной выгрузки.

**Шаг 3. Выполните одну команду расчёта.**

```powershell
python -B pipeline.py
```

Успешный запуск создаёт пять файлов в `out/` и печатает проверку входных данных, распределение ролей, пороги и первые пять кандидатов. Ожидаемые числа на выданных таблицах:

```text
node_count: 2248
edge_count: 3119
transaction_count: 4840
seed_count: 81
orphan_count: 19
edge_turnover: 365890012.01
CLUSTERS: 91
```

При проверенном запуске с отсутствующей папкой результатов полное время команды составило **0,909 с**. На другом компьютере время будет отличаться; требование кейса — менее 300 секунд. Запуск повторяемый: выходные файлы обновляются автоматически. Удалять их для обычного пересчёта не требуется.

**Шаг 4. Проверьте результат и откройте интерфейс.**

```powershell
python -B verify.py --data data --out out
python -m http.server 8765 --bind 127.0.0.1 --directory out
```

Оставьте терминал сервера открытым и перейдите в браузере на [http://127.0.0.1:8765/](http://127.0.0.1:8765/). Если этот сервер уже запущен, сразу откройте адрес. Подробнее о размещении — в разделе 5.

### Если организаторы предоставили Parquet

Положите `nodes.parquet`, `edges.parquet`, `transactions.parquet` в отдельную папку `parquet_data`. Создайте окружение и установите единственную зависимость — зафиксированный `pyarrow==25.0.1` из `requirements.txt`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -B pipeline.py --data parquet_data --out out
.\.venv\Scripts\python.exe -B verify.py --data parquet_data --out out
```

Интернет нужен при установке пакета; сам расчёт работает локально. Подготовьте окружение до выступления. Не смешивайте два формата в одном наборе: при наличии полного набора Markdown программа выбирает его раньше Parquet.

Исходных Parquet организаторов в этой сессии не было. Проверен полный набор, локально конвертированный из предоставленных Markdown: первый запуск занял **17,166 с**, повторный — **1,073 с**; независимая проверка прошла. Эти измерения подтверждают работу адаптера на конвертированном наборе. Оригинальные Parquet при получении нужно проверить той же командой.

## 4. Как самостоятельно проверить результат

### Проверка всех контрактов одной командой

```powershell
python -B verify.py --data data --out out --report .audit/final_checks.json
```

Признак успеха — строка `PASS: 2248 nodes, 3119 edges, 4840 transactions; 91 clusters; top 100.` и код завершения 0. Проверка занимает около **0,6–0,7 с** на этой машине. При обнаруженном расхождении она печатает `FAIL` и возвращает ненулевой код.

Проверяющий скрипт самостоятельно читает исходные таблицы и пересчитывает суммы, количества, направленные метрики, правила ролей и приоритет. Он сверяет точные CSV-колонки, полноту узлов, все числовые объяснения, оговорки для seed и глубины 4, группы, их гипотезы и данные встроенного интерфейса. Сохранение отчёта разрешено только в `.audit/*.json`. Корректность чисел не доказывает реальную роль клиента и не означает, что найдено единственное возможное разбиение на группы.

Дополнительные регрессионные проверки:

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
```

В проверенном окружении с `pyarrow` выполнено **26 тестов: 25 прошли, 1 пропущен**. Пропущена проверка создания настоящего symlink: Windows отказала в необходимой привилегии, ошибка 1314. Проверки junction, hardlink и сбоя атомарной записи прошли. Без `.venv` можно использовать `python -B -m unittest discover -s tests -v`; при отсутствии `pyarrow` дополнительно пропускается тест типов Parquet.

### Случайный узел: от CSV к исходным переводам

1. Выберите строку воспроизводимой случайной выборкой. Здесь `gid` остаётся строкой; не преобразуйте его в `float` и не позволяйте табличному редактору округлять 18 цифр.

```powershell
python -c "import csv, random; r=random.Random(20260923).choice(list(csv.DictReader(open('out/nodes_roles.csv', encoding='utf-8')))); print(r['gid']); print(r['evidence'])"
```

На текущем результате команда выбирает `100000005314565100`. В пояснении указаны глубина 3, один плательщик, три перевода, 218 500 KZT и отсутствие наблюдаемых исходящих.

2. Найдите **все** упоминания этого идентификатора в исходной таблице рёбер:

```powershell
Select-String -LiteralPath .\data\edges.md -SimpleMatch '100000005314565100'
Select-String -LiteralPath .\data\nodes.md -SimpleMatch '100000005314565100'
Select-String -LiteralPath .\data\transactions.md -SimpleMatch '100000005314565100'
```

В `edges.md` находится единственная строка:

```text
src                 dst                 sum_kzt  n_tx  depth
100000002957787100   100000005314565100   218500   3     3
```

Выбранный `gid` стоит в `dst`: это входящий перевод. Строк с ним в `src` нет. В `nodes.md` глубина узла — 3, флаг seed — false. В `transactions.md` три исходные операции по этой паре; их суммы дают 218 500 KZT. Значит, правило наблюдаемого `terminal` до глубины 4 и оценка 0,82 соответствуют выгрузке. Отсутствие исходящих здесь не подтверждает отсутствие иных операций за её пределами.

Для другого узла считайте отдельно: уникальные `src` во входящих строках — число плательщиков; уникальные `dst` в исходящих — число получателей; сумма `n_tx` — число переводов; сумма `sum_kzt` — объём. Доля пересылки равна исходящей сумме, делённой на входящую, только когда входящая положительна. У seed эта доля не используется для назначения транзитной роли или правила накопления по низкой доле пересылки.

3. Получите все рассчитанные признаки, сработавшее правило и прямые рёбра:

```powershell
python -B verify.py --data data --out out --gid 100000005314565100
```

|---|---|---:|---:|

## 5. Как разместить и открыть проект

Фактически использованный и проверенный путь — **локальный HTTP-сервер на этом компьютере**. Публикация во внешнем сервисе не выполнялась.

```powershell
cd C:\hackalemai
python -m http.server 8765 --bind 127.0.0.1 --directory out
```

Адрес: [http://127.0.0.1:8765/](http://127.0.0.1:8765/). Сервер отдаёт только содержимое `out/` и слушает `127.0.0.1`, поэтому рассчитан на браузер этого компьютера. Остановка — Ctrl+C в его терминале. Если порт занят уже запущенным сервером проекта, используйте открытый адрес.

**На площадке без интернета** используйте ту же команду: интернет для сервера и просмотра не нужен. Заранее сохраните код, три входные таблицы и готовую папку `out/` на ноутбуке. Альтернативный способ — открыть `out/index.html` как локальный файл: страница самодостаточна. Такой запуск через `file://` в этой сессии не проверен из-за ограничения браузерной автоматизации; проверенный резервный вариант — сервер на `127.0.0.1`.

Данные выданы исключительно для хакатона. Храните репозиторий команды приватным и не публикуйте `data/` или `out/` на GitHub Pages, Vercel либо другом открытом сайте без согласования разрешённых условий. Игнорирование этих папок в Git не ограничивает публикацию при ручной загрузке файлов. Подробности — [SECURITY.md](SECURITY.md).

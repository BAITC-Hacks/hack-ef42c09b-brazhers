### Технические точки контроля

- `pipeline.py`: `exact_int64`, `transaction_date`, `monetary_amount`, `validate_inputs` — входные значения и суммы.
- `read_parquet_tables` — только заданные поля и типы; несовместимая или дополнительная схема отклоняется.
- `prepare_output_directory`, `atomic_write_text` — проверка назначения и замена файлов.
- `dashboard_html` — экранирование сериализованного JSON; `viewer.html`, функция `el` — текстовые DOM-вставки.
- `verify.py` независимо сверяет граф, выгрузки и HTML; его `--report` допускает JSON только в собственной папке `.audit`.

Сам по себе явно заданный `--out другой_каталог` является штатным выбором локального назначения. Ошибка состояла в следовании существующим ссылкам при записи, а не в наличии этого параметра.

## Зависимости и CVE

Прежний диапазон `pyarrow>=14.0` допускал 14.0.0, входящий в диапазон CVE-2023-47248: обработка специально созданного файла могла привести к выполнению кода. Исправленная версия начинается с 14.0.1. Это риск разрешённого диапазона, а не свидетельство эксплуатации в проекте. [Проверенное уведомление GHSA-5wvp-7f3h-6wmm](https://github.com/advisories/GHSA-5wvp-7f3h-6wmm).

Также рассмотрен CVE-2026-25087 для Arrow C++ IPC reader с pre-buffering; исправление вошло в 23.0.1. Этот конкретный IPC-сценарий не используется читателем Parquet проекта. [Описание Apache Arrow](https://arrow.apache.org/blog/2026/02/16/23.0.1-release/).

Закреплён PyArrow 25.0.1, опубликованный Apache 10 августа 2026. [Официальный выпуск](https://arrow.apache.org/blog/2026/08/10/25.0.1-release/), [пакет PyPI](https://pypi.org/project/pyarrow/25.0.1/).

Pandas 3.0.6 пробно устанавливался при аудите, но Windows Application Control заблокировал его нативную DLL. Настройки Windows не изменялись. Чтение Parquet переведено на прямой PyArrow; pandas и его ненужные зависимости удалены из окружения проекта. NetworkX не используется. Риск pickle, описанный в [политике pandas](https://github.com/pandas-dev/pandas/security/policy), также не относится к используемому пути чтения.

Машинный результат проверки: `.audit/dependency_audit.json`. Аудиторский инструмент установлен отдельно от окружения пайплайна. Подготовка и повторение из корня проекта (установка требует интернета):

```powershell
python -m venv .audit\audit-env
.\.audit\audit-env\Scripts\python.exe -m pip install pip-audit==2.10.1
.\.audit\audit-env\Scripts\python.exe -m pip_audit -r requirements.txt --no-deps --disable-pip --progress-spinner off
```

`--no-deps` здесь допустим: установленный PyArrow не привёл к установке дополнительных runtime-пакетов. Отсутствие известных записей в базе на дату проверки не гарантирует отсутствия будущих уязвимостей. В `requirements.txt` закреплена версия, но нет кроссплатформенного lock-файла с хешами всех wheel-файлов.

## Данные и публикация

Организаторы разрешили использование обезличенного набора **исключительно в рамках хакатона**. Это ограничение относится и к производным CSV, и к `out/index.html`: HTML содержит всю сеть и вычисленные признаки, даже если на экране открыт только один узел. Рекомендуется закрытый репозиторий и согласованный с организаторами способ передачи результатов жюри. Данные заново копируются в `data/` из разрешённой выгрузки при подготовке чистой рабочей копии.

`.gitignore` предотвращает обычное добавление неотслеживаемых файлов; он не удаляет старые коммиты и не запрещает `git add -f`. Здесь история Git отсутствует, поэтому отсутствие данных в каком-либо внешнем репозитории подтвердить нельзя. При создании репозитория проверяйте подготовленный к коммиту список, включая документы с демонстрационными gid.

Фактически использованный просмотр:

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory out
```

Адрес: [локальное демо](http://127.0.0.1:8765/). Сервер отдаёт результаты только локальным клиентам. Это демонстрационный сервер без авторизации; он не предназначен для публичного хостинга. Публикация в GitHub Pages/Vercel не выполнялась.

## Проверки и оставшиеся границы

Полная команда `.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v` выполнила **26 тестов: 25 PASS, 1 SKIP**. Пропущена попытка создать реальную символическую ссылку: Windows вернул ошибку 1314, отсутствует нужная привилегия. Реальные junction и hardlink, защита старых файлов при отказе `os.replace`, испорченные CSV и потеря точности gid проверены успешно. Привилегии ради теста не менялись.

Защита файлов рассчитана на доверенный локальный каталог. Атомарность обеспечивается для одного файла; все пять результатов не являются одной файловой транзакцией. Одновременная подмена каталогов другим пользователем с правом записи не входит в гарантии. Большой недоверенный Parquet может потребовать значительную память; сервис приёма произвольных файлов и ресурсные квоты отсутствуют. Для другого месяца или другого порога требуется осознанно изменить контракт данных и проверки.
